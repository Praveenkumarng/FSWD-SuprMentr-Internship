1. What is Client-Server Architecture?

Client-server architecture is a computing model where two parties — the client and the server — communicate over a network. The client makes requests, and the server processes those requests and sends back responses.

  • Client: The user's device (browser, mobile app, etc.) that initiates requests.
  • Server: A powerful computer (or group of computers) that stores data and applications and responds to client requests.
  • Network: The communication medium (usually the Internet) that connects the client and server.

3. What Happens When You Open a Website?

When you type a URL (e.g., https://www.google.com) into a browser and press Enter, the following steps happen in sequence:

  1. Step 1 – URL Parsing
    The browser parses the URL into its parts:
    • Protocol: https:// (HyperText Transfer Protocol Secure)
    • Domain: www.google.com
    • Path: / (root page)

  2. Step 2 – DNS Lookup (Domain Name System)
    The browser does not know the IP address of www.google.com, so it asks a DNS server to translate the domain name into an IP address (e.g., 142.250.195.68). This process is called DNS Resolution.
    • Browser checks its own DNS cache first.
    • If not found, asks the OS, then the Router, then the ISP's DNS server.
    • If still not found, the DNS resolver queries root name servers → TLD servers → authoritative DNS server.
    • The IP address is returned to the browser.

  3. Step 3 – TCP Connection (Three-Way Handshake)
    The browser establishes a connection with the server using the TCP protocol: 
    
  Client  -------- SYN -----------------> Server   (Client: "Can we connect?")
  Client  <------- SYN-ACK -------------- Server   (Server: "Yes, ready!")
  Client  -------- ACK -----------------> Server   (Client: "Great, connected!")

  Connection Established.
    If HTTPS is used, a TLS handshake also occurs to establish an encrypted connection.

  4. Step 4 – HTTP Request
    The browser sends an HTTP GET request to the server: 
      GET / HTTP/1.1
  Host: www.google.com
  User-Agent: Mozilla/5.0 ...
  Accept: text/html

  5. Step 5 – Server Processes the Request
    The web server receives the request and:
    • Routes the request to the appropriate application (e.g., PHP, Node.js).
    • The application may query a database for dynamic content.
    • Generates an HTML response.

  6. Step 6 – HTTP Response
    The server sends back an HTTP response: 
      HTTP/1.1 200 OK
  Content-Type: text/html
  Content-Length: 5893

  <!DOCTYPE html>
  <html>...</html>

  7. Step 7 – Browser Renders the Page
    The browser receives the HTML and renders it step by step:
    • Parsing HTML → builds the DOM tree.
    • Parsing CSS → builds the CSSOM (CSS Object Model).
    • Combining DOM + CSSOM → creates the Render Tree.
    • Layout → calculates size and position of each element.
    • Painting → draws pixels on the screen.
    • JavaScript Execution → JS is parsed and executed, which may modify the DOM dynamically.
    • Additional resources (images, CSS, JS files) are fetched with separate HTTP requests.

  8. Step 8 – Page is Displayed
    The fully rendered page is now visible to the user in the browser window.

5. Key Terms

Term Full Form Meaning
HTTP HyperText Transfer Protocol Protocol used to transfer web data between client and server.
HTTPS HTTP Secure Encrypted version of HTTP using TLS/SSL.
DNS Domain Name System Translates human-readable domain names to IP addresses.
TCP Transmission Control Protocol Reliable protocol that ensures data is delivered correctly.
IP Internet Protocol Numerical address identifying a device on the network.
URL Uniform Resource Locator The web address used to locate a resource on the Internet.
DOM Document Object Model Tree structure representing the HTML document in memory.
TLS Transport Layer Security Cryptographic protocol that provides secure communication.
